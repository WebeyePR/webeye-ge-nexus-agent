# 基于 Vertex AI 的企业级飞书 RAG 完整实施方案

## 1. 架构概览与核心理念

本方案旨在利用 Google Cloud 的前沿 AI 技术（Vertex AI Search & Gemini）对飞书现有的知识管理体系进行企业级改造。核心目标不仅是提升搜索的**语义理解精度**和**多模态处理能力**，更关键的是在底层实现**严格的数据权限隔离（Zero Trust）**。

### 核心流转链路：
1. **身份流**：飞书组织架构 -> Google Cloud Identity (Group/User)
2. **数据流**：飞书非结构化数据 (带飞书权限) -> ACL 转换 -> Google Cloud Storage (附带 `acl_info` 元数据) -> Vertex AI Search 索引
3. **查询流**：飞书用户提问 -> 换取 Google OAuth Token -> Vertex AI Search 底层权限过滤检索 -> Semantic Ranker 重排 -> Gemini 多模态总结 -> 返回安全结果

## 2. 实施步骤与官方支持可行性分析

根据 `@[/Code]` 规范，所有的开发规划都必须拆解为独立、可验证的步骤，并在实施前确认其技术可行性与官方支持情况。

### 阶段一：身份认证与组织架构同步 (Identity & ACL Mapping)

*   **目标**：将飞书的权限模型映射到 Google 生态中，为底层权限校验提供身份基础。
*   **可行性分析（100% 可行且官方支持）**：
    *   根据 Google Cloud 官方文档《Set up data source access control》，Vertex Search 原生支持基于 **Google Identity** 或 **Workforce Identity Federation** 的文档级访问控制 (Document-level Access Control)。
*   **实施细则**：
    1.  **架构初始化**：在 Google Workspace 或 Cloud Identity 中开通企业目录服务。
    2.  **数据拉取**：开发同步中间件，调用飞书开放平台“通讯录 API”（获取部门、用户组、人员列表）。
    3.  **身份映射**：将飞书的部门/角色映射为 Google Cloud Identity 的 `Groups`，飞书员工映射为 `Users`。
    4.  **增量更新**：配置飞书 Webhook 订阅通讯录变更事件，实时将人员的入职、离职、调岗同步至 Google Identity。
*   **验收标准**：飞书新增一个测试部门及员工后，5秒内在 Google Identity 控制台能看到对应的 Group 和 User。

### 阶段二：全量多模态数据安全摄入 (Data Ingestion & ACL Labeling)

*   **目标**：安全地提取飞书数据并构建带权限标签的底层向量检索库。
*   **可行性分析（100% 可行且官方支持）**：
    *   Vertex AI Search 官方文档明确说明：在从 Cloud Storage (GCS) 或 BigQuery 导入数据时，支持通过 JSON Lines (JSONL) 元数据文件传入 `acl_info` 字段，实现文档级权限打标。
*   **实施细则**：
    1.  **数据拉取服务**：调用飞书云文档 API、消息记录 API 导出企业知识库内容及历史聊天记录。
    2.  **数据清洗与格式化**：将飞书富文本转为纯文本或 Markdown 格式。对于视频、语音等妙计内容，保存为 Gemini 可解析的多模态文件。
    3.  **ACL 注入 (关键步)**：在生成待上传的元数据 (metadata.jsonl) 时，读取该文档在飞书中的权限关系，并转译为 Google Identity 格式写入 `acl_info`。
        ```json
        {
          "id": "doc_123",
          "content": "CEO关于2025年战略规划的会议纪要...",
          "acl_info": {
            "readers": [
              {"group": "executives@yourdomain.com"},
              {"user": "ceo@yourdomain.com"}
            ]
          }
        }
        ```
    4.  **构建索引**：将数据和元数据上传至 Google Cloud Storage，触发 Vertex AI Search 执行增量或全量索引构建。
*   **验收标准**：在 Vertex Search 控制台中抽查数据，确认每条记录的 ACL 属性已成功录入且准确对应了 Google Group。

### 阶段三：基于身份凭证的安全检索与问答 (Secure Retrieval & RAG)

*   **目标**：在用户无感知的状态下，实现底层防越权拦截与高质量的 AI 问答总结。
*   **可行性分析（100% 可行且官方支持）**：
    *   Google 官方支持在调用搜索 API 时，传入最终用户的 OAuth 2.0 Access Token。Vertex 搜索引擎会在底层校验该 Token 是否命中数据的 `acl_info`，完全不依赖前端过滤。
    *   Vertex AI Ranking API (Semantic Ranker) 已 GA，提供基于 Google 核心算法的语义重排序。
*   **实施细则**：
    1.  **凭证换取**：当飞书用户在对话框提问时，中间件获取飞书 User ID，并以此换取该用户在 Google Identity 下的临时 OAuth 2.0 Access Token。
    2.  **带权检索**：携带用户的 Query 和 Access Token 调用 Vertex AI Agent Search API。
    3.  **语义重排**：在 Search API 参数中开启 `Semantic Ranker`，对初步召回的内容进行精准重排，解决模糊提问痛点。
    4.  **大模型生成**：检索出的“合法且高相关”的 Document Chunks 连同用户的原始问题，一起 Prompt 送入 Gemini 1.5 Pro 大模型。
    5.  **多模态推理**：如果召回了视频或图片片段，Gemini 可原生处理并生成包含多模态引用的总结内容，返回至飞书对话框。
*   **验收标准**：
    *   安全防线：使用实习生账号提问“2025战略规划”，模型回答“未找到相关信息”（底层拦截）；使用高管账号提问相同内容，模型准确总结。
    *   语义能力：使用高度模糊口语（“就那个上个月李总说的关于费用的事”）能精准召回对应文档并总结。

## 4. 技术栈选型建议

1. **核心计算引擎**: Google Cloud Run (用于部署所有的数据同步、API 对接及中转逻辑，提供 Serverless 的高可用伸缩)
2. **中间件语言**: Python (FastAPI) 或 Node.js，便于对接 Google Cloud SDK 和飞书 SDK。
3. **数据库 / 状态存储**: Firestore (用于存储同步状态、映射关系缓存及聊天上下文 Session)。
4. **大模型服务**: Vertex AI Search (Enterprise Search), Vertex AI Gemini 1.5 Pro/Flash API。

## 5. 项目风险与缓解策略

- **风险 1：飞书接口调用频率限制 (Rate Limit)**
  - *缓解策略*：采用消息队列 (Cloud Tasks / PubSub) 削峰填谷，平滑数据拉取请求；全量同步放在业务低谷期。
- **风险 2：权限同步延迟导致的数据越权空窗期**
  - *缓解策略*：采用实时 Webhook 优先的策略，一旦人员离职或权限变动，最高优先级触发 Identity 同步。同时在飞书端拦截异常频次的跨部门搜索请求。
